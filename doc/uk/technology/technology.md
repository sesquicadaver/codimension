Технологія візуалізації — огляд
================================

Вступ
-----

Технологія Codimension дозволяє реалізувати інструменти розробника з двома
синхронізованими поданнями одного й того ж коду: текстовим редактором і
автоматично згенерованою блок-схемоподібною діаграмою. Вікно IDE розділене
на дві частини — зліва звичний текстовий редактор, справа — діаграма потоку
керування, яка оновлюється під час пауз у наборі тексту, якщо код залишається
синтаксично коректним. Користувач працює одночасно з текстом і його
графічним представленням.

Питання про доцільність блок-схем у сучасній розробці має практичну відповідь.
При створенні нового ПЗ часто використовується підхід зверху вниз: спочатку
архітектура абстрактними блоками, потім деталізація до рівня мови
програмування. При супроводі існуючого коду — знизу вверх: читаючи код,
розробник ментально або на папері замінює групи операторів одним блоком з
міткою. Ідеальний інструмент підтримував би обидва напрямки без втрати
текстового представлення, з плавним перемиканням між видами.

Історично блок-схеми масово застосовувалися в критичних системах — зокрема в
програмному забезпеченні космічного челніка «Буран», де мова DRAKON
використовувала діаграми на всіх етапах розробки. Сучасні мови загального
призначення не дозволяють повторити DRAKON один-в-один, але висновок
залишається: діаграми, подібні до блок-схем, корисні і можуть підвищити
якість та швидкість розробки.

На ринку немає інструменту, що однаково добре поєднує текст і графіку з
автоматичною синхронізацією. Універсальні графічні редактори (Dia, Visio)
погано підходять для частих змін коду; UML-інструменти — для високого рівня
абстракції; генератори коду часто дають текст, не призначений для читання.
Codimension — експерimentalна IDE, що реалізує цю технологію для Python.

Подвійне подання IDE
--------------------

Codimension відхилила підхід «лише графіка»: інфраструктура IT-проєктів
(контроль версій, пошук, diff) зав'язана на текст. Робоча область IDE
поділена між текстовим редактором і графічним поданням.

Реалізовані можливості синхронізації:

- автоматичне оновлення діаграми під час пауз у наборі; при синтаксичних
  помилках діаграма не оновлюється, індикатор стану повідомляє про це;
- подвійний клік на примітиві — перехід до відповідного рядка в редакторі;
- гаряча клавіша — прокрутка діаграми до примітиву, що відповідає
  поточному рядку курсора;
- панель навігації по вкладених scope під курсором;
- масштабування; експорт у SVG, PDF і PNG.

Графічні примітиви (коротко)
----------------------------

Перехід від тексту до діаграми вимагає розпізнання елементів мови та
вибору форми для кожного.

**Блоки коду** — прямокутники для операторів, що не впливають безпосередньо
на потік керування. Групування за порожніми рядками зберігається.

**Коментарі** — три типи: незалежні (між блоками, з горизонтальним
з'єднувачем), leading (без порожнього рядка перед наступним оператором),
side (праворуч від рядка, з вирівнюванням по рядках і «хвостом» для
багаторядкових side-коментарів).

**Імпорти** — з іконкою зліва, щоб одразу виділяти залежності модуля.

**if/elif/else** — компромісна форма (діамантоподібні боки, плоскі верх/низ).
Гілка «так» — під блоком умови, «ні» — праворуч (основний шлях на вертикальній
осі). CML `sw` перемикає розташування гілок.

**Функції, класи, декоратори** — scope-примітиви (закруглений прямокутник з
заголовком, badge, docstring). Side-коментарі до аргументів — у заголовку.

**return, raise, assert, sys.exit()** — спеціальні форми з іконками;
raise/assert — червона стрілка; assert — умовний характер через діамант.

**Цикли for/while** — scope з умовою в заголовку; else — праворуч з
пунктирним з'єднувачем. break/continue — мітки без вихідних з'єднувачів.

**try/except/else/finally** — окремий scope для кожної частини; except —
праворуч, else/finally — під try.

**with** — scope для контекстного менеджера.

**Файл (модуль)** — scope з shebang, encoding і docstring модуля.

Парсери форку (brief_ast / flow_ast)
------------------------------------

Codimension — відкритий проєкт під GPL v3. Оригінальна архітектура: два C/C++
розширення [cdm-pythonparser](https://github.com/SergeySatskiy/cdm-pythonparser)
та [cdm-flowparser](https://github.com/SergeySatskiy/cdm-flowparser) плюс
[IDE](https://github.com/SergeySatskiy/codimension). Оригінальні репозиторії
не підтримуються понад 4 роки.

**Цей форк** використовує pure-Python fallback-парсери (`brief_ast`, `flow_ast`),
коли C-розширення недоступні (Python 3.10+). UI — PyQt5. Розробка ведеться на
Linux (Ubuntu). Підтримується Python 3.10–3.13. Встановлення — лише з вихідного
коду форку ([doc/INSTALL.md](../../INSTALL.md)).

**brief parser** (або `brief_ast`) збирає сутності файлу: імпорти, класи,
функції, глобальні змінні, docstring — для outline, аналізу мертвого коду,
вкладок Classes/Functions/Globals.

**flow parser** (або `flow_ast`) будує структуру потоку керування для
малювання діаграми: блоки, функції, умови, цикли тощо з фрагментами
(початок/кінець у тексті).

Нормативний контракт позицій, brief/flow семантики та тестів:
[parser-contract.md](parser-contract.md).

Pipeline: від коду до графіки
-----------------------------

Перехід реалізовано як конвеєр (pipeline):

1. **Синтаксичне дерево** — парсинг коду; у класичній реалізації через API
   інтерпретатора Python; коментарі в дереві відсутні.
2. **Збір коментарів** — окремий прохід по рядках.
3. **Злиття** — коментарі прив'язуються до елементів (leading, side).
4. **Віртуальний canvas** — розміщення елементів у двовимірній сітці
   (рядки/стовпці), scope розбивається на кути та ребра.
5. **Rendering** — розрахунок мінімальних і фактичних розмірів комірок з
   урахуванням сусідніх рядків (особливо для if з гілками різної ширини).
6. **Drawing** — створення QT Graphics Scene і відмальовування елементів.

Етапи 1–3 виконуються в flow parser (C/C++ у оригіналі; у форку — Python
fallback). Етапи 4–6 — у IDE на Python для гнучкості експериментів.

CML — коротко
-------------

Додаткова розмітка діаграм (кольори, заміна тексту, перемикання гілок if,
групування) зберігається **в Python-коментарях** у вихідному коді — мова
CML (Codimension Markup Language). Формат:

```python
# cml <version> <type> [key=value pairs]
# cml+ <продовження>
```

Основні типи: `rt` (replace text), `sw` (switch гілок if), `cc` (custom
colors), `gb`/`ge` (початок/кінець візуальної групи), `doc` (посилання на
документацію). Деталі — у [doc/uk/cml/cml.md](../cml/cml.md).

Реалізовані можливості
----------------------

- автоматичне оновлення діаграми;
- двостороння синхронізація текст ↔ графіка;
- масштабування; експорт PDF/PNG/SVG;
- навігація по scope;
- перемикання гілок if (контекстне меню + CML `sw`);
- заміна відображуваного тексту примітивів (CML `rt`, tooltip з оригіналом);
- індивідуальні кольори (CML `cc`);
- групування блоків (CML `gb`/`ge`; smart zoom; приховування елементів).

Заплановано або частково реалізовано: синхронізація прокрутки, редагування
на діагramі, візуалізація налагодження, пошук на діаграмі, друк, підсвічування
типів імпортів.

Побічні ефекти та застосовність
-------------------------------

Практика показала неочікувані переваги: діаграми зручні для документації та
обговорень з нетехнічними експертами (псевдокод на Python синтаксисі +
миттєве оновлення діаграми). Психологічний ефект — «занадто заплутана»
діаграма мотивує рефакторинг коду для простішого потоку. Технологія
застосовна й до інших мов; Python обрано через популярність і просту граматику.

розділу CML v.1 та архітектури IDE — у повному англомовному документі:
