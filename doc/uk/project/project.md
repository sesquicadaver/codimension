Проєкт
=======

Codimension підтримує роботу з проєктом і без нього.

**Запуск:** IDE стартує без автоматичного завантаження останнього проєкту (для швидкого
запуску з великими проєктами). Використовуйте вкладку **Recent** у лівій бічній панелі,
щоб обрати проєкт для завантаження (подвійний клік або кнопка Load).

Якщо проєкт не завантажено, усі відкриті файли вважаються незалежними без
зв'язку між собою. Частина функціональності IDE буде недоступною в цьому
випадку, наприклад побудова діаграми залежностей для всіх Python-файлів проєкту.

Проєкт у Codimension — це каталог і все, що знаходиться нижче рекурсивно. При
створенні проєкту Codimension є два основних варіанти:

- Вказати неіснуючий каталог. У цьому випадку Codimension створить
  каталог.
- Вказати існуючий каталог. У цьому випадку вся структура файлової системи
  нижче буде проаналізована, і всі файли та каталоги вважатимуться
  частиною проєкту.

В обох випадках Codimension створить файл проєкту у форматі JSON з
властивостями проєкту. Файл називатиметься:

```
<каталог проєкту>/<назва проєкту>.cdm3
```

Щоб створити проєкт, скористайтеся пунктом головного меню `Project -> New project`.
Після підтвердження створення Codimension завантажить проєкт. Назва поточного
завантаженого проєкту відображається на вкладці проєкту у верхній панелі:

![Вкладка проєкту](../../project/projectbar.png "Вкладка проєкту")

Панель проєкту має дві кнопки. Одна — для вивантаження проєкту, інша —
для перегляду або редагування властивостей проєкту.

Діалог створення проєкту виглядає так:

![Діалог створення проєкту](../../project/projectdialog.png "Діалог створення проєкту")

Це набір полів вводу для вказання властивостей проєкту.

| Поле вводу           | Опис |
|:---------------------| ----------- |
| Project name         | Обов'язкове. Назва проєкту |
| Project directory    | Обов'язкове. Каталог проєкту |
| Main script          | Необов'язкове. Якщо вказано — має бути Python-скриптом. Використовується при налагодженні або профілюванні проєкту. |
| Markdown doc file    | Необов'язкове. Якщо вказано — має бути markdown-файлом. Показується при запиті документації проєкту. |
| Python interpreter   | Необов'язкове. Шлях до каталогу venv або виконуваного файлу Python для аналізу проєкту (ruff, mypy, pytest, резолв імпортів тощо). Залиште порожнім, щоб використовувати Python IDE. Автоматично визначає `.venv`, `venv`, `env` у корені проєкту, якщо не вказано. Краще створити/підключити через Tools → Project utilities → **VENV…**. venv автоматично виключається з аналізу. |
| Import directories   | Необов'язкове. Список каталогів, де розташовані Python-файли, доступні для нерелятивного імпорту з інших файлів проєкту. Використовується при розв'язанні імпортів у файли (наприклад, для діаграми залежностей). |
| Exclude from analysis | Необов'язкове. Каталоги або файли для виключення з аналізу (діаграма імпортів, outline, вкладки Classes/Functions/Globals). Шляхи можуть бути відносними до проєкту або абсолютними. venv виключається автоматично. |
| Version              | Необов'язкове. Версія проєкту. |
| Author               | Необов'язкове. Автор проєкту. |
| E-mail               | Необов'язкове. E-mail автора. |
| License              | Необов'язкове. Ліцензія проєкту. |
| Copyright            | Необов'язкове. Авторське право на код. |
| Description          | Необов'язкове. Опис проєкту. |
| Default encoding     | Необов'язкове. Кодування за замовчуванням проєкту. Використовується, наприклад, при відкритті файлу для редагування. |
| Creation date        | Генерується автоматично, не для редагування |
| UUID                 | Генерується автоматично, не для редагування |

Майже всі властивості проєкту доступні для підстановки в шаблон нового файлу
проєкту. Такий шаблон можна створити окремо.

UUID проєкту використовується для його ідентифікації. Для кожного проєкту Codimension
створює каталог за адресою

```
~/.codimension3/<UUID>/
```

де зберігається все середовище проєкту: історія пошуку, відкриті файли,
позиції в них тощо.

Коли проєкт завантажено, Codimension заповнює вкладку проєкту всіма
файлами проєкту:

![Вкладка проєкту](../../project/projecttab.png "Вкладка проєкту")

Також вкладки Classes, Functions і Globals заповнюються відповідними
елементами з усіх файлів проєкту. Ці вкладки мають засоби пошуку, що дозволяють
швидко знайти потрібне місце в коді.

Жодних ручних дій не потрібно, коли до проєкту додаються або з нього
видаляються файли. Codimension стежить за каталогами проєкту на зміни та
оновлює вкладки відповідно. Нові файли можна створити в IDE або
скопіювати/створити іншими способами поза IDE. Те саме стосується
видалення файлів або каталогів.

### Середовище аналізу (T140 / T141 / R176)

Порядок вибору Python для резолву імпортів і запуску плагінів:

1. **configured** — `pythoninterpreter` у `.cdm3` (властивості проєкту або збереження з **VENV…**)
2. **session** — тимчасовий overlay після **VENV…** / auto-attach, якщо не зберегли в проєкт
3. **auto** — кореневий `.venv` / `venv` / `env`, якщо є
4. **IDE** — `sys.executable` процесу Codimension

Якщо `pythoninterpreter` заданий, але не резолвиться — **Env: broken** (аналіз на fallback; mutate заборонено).

У status bar: **Env: project | session | auto | IDE | broken** (tooltip — шлях + підказка). Подвійний клік по **Env:** відкриває **VENV…** / **Update VENV…**.

**Options → Project venv on open** (`projectVenvPolicy`, R176):

| Політика | Поведінка при open |
|----------|--------------------|
| `manual` | Без auto-attach |
| `auto_session` (**default**) | Перший кореневий venv → session overlay |
| `auto_persist` | Те саме + запис у `.cdm3` |

При **broken** configured або **IDE** + `requirements*.txt` / `pyproject.toml` — WARNING у лог з підказкою на **VENV…**. Auto-create немає.

**Tools → Project utilities → VENV…** (коли `pythoninterpreter` порожній або broken): create/attach, опційний pip. **Update VENV…** при broken перенаправляє на **VENV…**. Після setup/update — re-analyze імпортів.

Unresolved для pip — **opt-in** (за замовчуванням вимкнено) з multi-select.

### Log → джерело (R177)

Помилки аналізу імпортів у вкладці **Log** мають префікс `шлях:рядок: …`.
**Подвійний клік** по такому рядку відкриває файл у редакторі на вказаному рядку
(курсор-рука при наведенні). Рядки без локації ігноруються.

### Плагіни lint/test і project venv (R178 / R179)

Драйвери (`ruff`, `mypy`, `bandit`, …) перевіряють код через **project Python**.
Якщо модуля інструмента там немає — діалог: **встановити в project venv**
(`pip install …`) або опційно **Use IDE tools once** (site-packages проєкту
лишаються в `PYTHONPATH`). Тихого fallback на IDE немає — Cancel дає м’яке
повідомлення замість traceback `No module named`.

### Виключення шляхів з аналізу

Шляхи з **Exclude from analysis** (властивості проєкту) та venv проєкту
(Python interpreter) виключаються з графа аналізу, діаграми імпортів,
вкладок Classes/Functions/Globals і file watcher. Вони не захаращують
аналіз. Браузер проєкту все одно показує повне дерево каталогів; зменшується
лише область аналізу.
